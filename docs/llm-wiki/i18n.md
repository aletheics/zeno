# 国际化（i18n）规范

## 机制

- 文件：`apps/desktop/src/renderer/lib/i18n.ts`。
- 语言：`Locale = "zh" | "en"`。默认 `DEFAULT_LOCALE = "zh"`。
- 数据结构：一个 `messages` 对象，含 `zh` 与 `en` 两个块，`as const`。
- **键源是 `zh`**：`MessageKey = keyof (typeof messages)["zh"]`。
- 取值：`t(locale, key, vars?)`。

```ts
export function t(locale: Locale, key: MessageKey, vars?: Record<string, string>): string
```

## 规则

1. **所有用户可见文案**都走 `t()`，任何语言都不许硬编码在 JSX 里。
2. **新增键必须在 `zh` 和 `en` 两个块里都加。**
   - TypeScript 已强制 `en` 覆盖 `zh` 的每个键（`MessageKey` 会索引 `messages.en`），漏加 `en` 会编译报错。
   - 反向（只加 `en` 不加 `zh`）不会被编译器抓到，属于「死键」，别这么干。
3. **键命名**：`domain.section.subkey`，点分隔，叶子用 camelCase。例如 `terminal.cursorStyleHint`、`piSettings.steeringModeHint`。
4. **插值**：文案里写 `{var}`，调用时 `t(locale, key, { var: "值" })`；实现是 `replaceAll`，所以变量名别和文案正文撞词。
5. **不要在代码里 fork 日期 / 数字格式**：统一用 `Intl.DateTimeFormat` / `Intl.NumberFormat` 配 locale，不要写 `if (locale === "zh") ...`。

## 导入方式

组件里按需导入（路径是 `../lib/i18n.ts` 或 `@/lib/i18n`）：

```ts
import { t, type Locale, type MessageKey } from "../lib/i18n.ts";
```

## 测试

- 每个新键 / 新页面在 `apps/desktop/src/renderer/lib/i18n.test.ts` 补一条 spot check（`t("zh", key)` 与 `t("en", key)`）。
- `i18n.test.ts` 里的 `i18n key sync` 用例做**双向锁步**断言：zh 与 en 的键集合必须完全一致，任一侧缺键/多键直接 fail（`messages` 表已从 `i18n.ts` 导出供该用例读取）。
- 两层防线互为补充：
  - **编译期**（TS7053）：`MessageKey = keyof messages["zh"]`，`t()` 里的 `messages.en[key]` 让「只加 zh 不加 en」直接报错。
  - **运行期**（锁步测试）：抓到「只加 en 不加 zh」的死键 —— 编译器抓不到的反向，正好由测试兜住。
